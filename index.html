RLHF Evaluation Sample — Trainer @ Revelo (Claude AI)

Representative example of my real RLHF evaluation workflow. The task below is illustrative (actual client data is confidential) — the process, criteria and iteration count are exactly how I work.

ISSUE PULLED FROM GITHUB

parse_dates() raises ValueError on
ISO 8601 strings with a UTC offset,
e.g. "2024-03-11T10:00:00+02:00"

MODEL RESPONSE — ATTEMPT 1

def parse_dates(s):
    return datetime.strptime(
        s, "%Y-%m-%dT%H:%M:%S"
    )
# fails: format has no offset spec,
# still breaks on naive-only inputs

MY EVALUATION (Prompt 1)

  • Fails stated requirement: offset-aware strings
  • No handling for "Z" suffix
  • Score: 2/5 — sent back with failing test cases

MODEL RESPONSE — ATTEMPT 3 (final)

def parse_dates(s):
    return datetime.fromisoformat(
        s.replace("Z", "+00:00")
    )
# handles offsets, "Z" suffix,
# and naive timestamps

MY EVALUATION (Prompt 3)

  • Passes all provided edge cases
  • Matches repo style conventions
  • Score: 5/5 — approved, documented for engineering team

METHODOLOGY

RLHF loop, min. 3 prompts/task, defined rubric scoring, written feedback per iteration.

Ingestion & Processing pypdf (In-Memory Streaming Data Pipelines)

🔍 ARCHITECTURAL NOTE: Why RAG over Raw Local LLMs?

Even in high-security, completely local environments utilizing tools like Ollama, raw context stuffing scales quadratically at O(N²) compute complexity—causing extreme memory bottlenecks and performance degradation. This architecture mitigates attention loss and token bloat by using mathematical semantic pruning via Qdrant prior to generation, ensuring sub-50ms context filtering while fully supporting air-gapped on-prem deployments.
